# Выкладка на analysium.space

Пошагово, от чистого сервера до работающего сайта. Делается один раз, занимает
минут двадцать, из которых половина — ожидание сборки.

Всё, что нужно на сервере: Docker. Node, Postgres, сертификаты и почтовый клиент
живут внутри контейнеров — ставить их отдельно не надо.

---

## 1. Сервер

Подойдёт любой VPS с 2 ГБ памяти и 20 ГБ диска. Меньше памяти — сборка фронта
может не уложиться; в этом случае соберите образы на своей машине и загрузите
готовые, но проще взять сервер с запасом.

Нужен Ubuntu 22.04 или новее (годится любой дистрибутив с Docker).

**Проверьте перед началом:**

```bash
docker --version          # должно быть 24+
docker compose version    # должно быть v2+
```

Если Docker не стоит:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # чтобы не писать sudo; нужен перезаход в сессию
```

**Порты 80 и 443 должны быть открыты наружу.** Если включён firewall:

```bash
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
```

---

## 2. Домен

В панели регистратора домена `analysium.space` заведите A-запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP вашего сервера |

Если нужен ещё и `www` — добавьте вторую A-запись с именем `www` на тот же IP и
впишите оба имени в `DOMAIN` через запятую (Caddy получит сертификат на оба).

**Дождитесь, пока запись разойдётся, и только потом запускайте стек.** Caddy
пойдёт за сертификатом сразу при старте, и если домен ещё не указывает на
сервер, Let's Encrypt откажет, а повторные попытки упрутся в лимит на неделю.

Проверка с сервера:

```bash
dig +short analysium.space     # должен вернуть IP этого сервера
```

## 3. Код и настройки

```bash
git clone git@github.com:BOWI1618/analysium.git
cd analysium
cp .env.production.example .env.production
```

Откройте `.env.production` и заполните. Обязательное:

```bash
DOMAIN=analysium.space
ADMIN_EMAIL=ваша@почта            # сюда Let's Encrypt пишет об истечении
POSTGRES_PASSWORD=                # сгенерируйте, см. ниже
SESSION_SECRET=                   # сгенерируйте, см. ниже
```

Сгенерировать секреты:

```bash
openssl rand -base64 36           # для POSTGRES_PASSWORD
openssl rand -base64 48 | tr -d '\n/+=' # для SESSION_SECRET
```

`SESSION_SECRET` менять потом нельзя — смена подписи разлогинит всех разом.

**Регистрацию пока оставьте открытой** (`ALLOW_PUBLIC_REGISTRATION=true`) —
иначе вам не создать первый аккаунт. Закроем на шаге 6.

**Почту пока оставьте выключенной** (`MAIL_ENABLED=false`). Подключим на шаге 7,
когда сайт уже поднимется: с включённой почтой и неверными настройками SMTP
регистрация не завершится, и разбираться придётся сразу с двумя вещами.

---

## 4. Запуск

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Первая сборка — 5–10 минут. Дальше:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production ps
```

Все четыре сервиса (`db`, `api`, `web`, `backup`) должны быть `Up`, а `api` —
`healthy`. Если `api` висит в `starting` дольше минуты, смотрите логи:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production logs api
```

Миграции применяются сами при старте — руками ничего запускать не нужно.

---

## 5. Проверка

Откройте `https://analysium.space`. Должна открыться страница входа по HTTPS,
без предупреждений браузера.

Если сертификат не выдался, смотрите логи Caddy:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production logs web
```

Самая частая причина — домен ещё не указывает на сервер (вернитесь к шагу 2)
или порт 80 закрыт: Let's Encrypt проверяет владение именно по нему.

---

## 6. Первый аккаунт и закрытие регистрации

Нажмите «Создать аккаунт», заведите себя. Вы получите своё пространство и роль
владельца. Демо-данные в продакшен не заливаются — пространство будет пустым.

Затем закройте публичную регистрацию, чтобы форма не осталась открытой всему
интернету:

```bash
# в .env.production
ALLOW_PUBLIC_REGISTRATION=false
```

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --no-deps api
```

Вход существующих аккаунтов это не затрагивает.

---

## 7. Почта

Без неё не работают приглашения — а после шага 6 это единственный способ
добавить человека. Так что шаг обязательный, просто отложенный.

Подойдёт любой SMTP. Для команды из пяти человек объём — единицы писем в день,
в лимиты вы не упрётесь:

| Вариант | Бесплатно |
|---|---|
| Почта на своём домене (Яндекс 360, Mail.ru) | да |
| Brevo | 300 писем в сутки |
| Resend | 3000 в месяц |
| Обычный почтовый ящик | да, порядка 500 в сутки |

Заполните в `.env.production`:

```bash
MAIL_ENABLED=true
SMTP_HOST=smtp.вашпровайдер.ru
SMTP_PORT=587
SMTP_USER=логин
SMTP_PASSWORD=пароль_приложения
MAIL_FROM="FlowDesk <no-reply@analysium.space>"
```

Порт 465 — шифрование сразу, 587 — с переходом на TLS; код выбирает режим сам по
номеру порта. Для Яндекса и Gmail нужен **пароль приложения**, а не обычный
пароль от ящика.

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --no-deps api
```

Проверьте, что письма уходят: пригласите себя на второй адрес (настройки
пространства → участники) и посмотрите логи:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production logs api | grep mail
```

`mail sent` — всё хорошо. `mail failed` — рядом будет причина.

**Важно:** с этого момента новые регистрации требуют подтверждения адреса.
Ваш аккаунт и все, кто завёлся до включения почты, работают как работали.

---

## 8. Команда

Настройки пространства → участники → почта и роль. Человеку уходит письмо со
ссылкой, по ней он задаёт имя и пароль и сразу оказывается внутри. Ссылка
одноразовая, живёт 14 дней, повторное приглашение выдаёт новую.

## Дальше

**Обновление:**

```bash
git pull
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Данные переживают пересборку: база, загруженные файлы и сертификаты лежат в
именованных томах.

**Резервные копии** снимаются сами раз в сутки, хранятся 14 дней. Проверить, что
они восстанавливаются (это стоит сделать хотя бы раз):

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backup sh -c '
  createdb -h db -U $POSTGRES_USER restore_check &&
  pg_restore -h db -U $POSTGRES_USER -d restore_check $(ls -t /backups/*.dump | head -1) &&
  psql -h db -U $POSTGRES_USER -d restore_check -c "select count(*) from users" &&
  dropdb -h db -U $POSTGRES_USER restore_check'
```

Копии лежат на том же сервере, что и база: это спасает от испорченной миграции
или удалённых данных, но не от потери сервера. Если данные важны — копируйте том
`backups` куда-нибудь наружу.

**Логи** ограничены пятью файлами по 10 МБ на сервис, диск не забьют.

---

## Что стоит знать заранее

Второй инстанс API запускать нельзя: шина событий реального времени работает
внутри процесса, и вкладки на разных процессах перестанут видеть изменения друг
друга. Для пяти человек одного инстанса хватает с большим запасом.

Загруженные в задачи файлы лежат в томе `uploads` и в дамп базы не попадают —
если решите делать внешние копии, берите оба тома.
